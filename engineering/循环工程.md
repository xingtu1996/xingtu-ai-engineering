# 工程实践-循环工程（Loop Engineering）

> 定义：把每次使用当成一次进化——**使用→问题→沉淀→反哺→下次自动拦截**的闭环。每个产出有落点（零黑盒），错只犯一次，harness 越用越强。
> 示例企业依据：harness 哲学「复利进化/沉淀反哺/自进化/循环门禁」+ `memory/bad-case-index.md`（坑→BCI→Gate→自动拦截）。

## 一、复利循环模板

```
使用 → 问题 → 沉淀(incidents/BCI/research) → 反哺(红线/Gate/规则/脚本) → 下次自动拦截 → 回环使用
```
每转一圈多拦一个坑。

执行：① 使用做任务 → ② 发现 Bug/踩坑/新认知 → ③ 按类型落盘（证据链：代码引用+数据/日志）→ ④ 提炼可执行拦截手段（红线/Gate/规则/脚本）→ ⑤ 下次由机制挡住，不靠记忆。无拦截价值的沉淀不必反哺。

## 二、骨架表

| 循环节点 | 落盘位置 | 触发方式 |
|---------|---------|---------|
| Bug / 生产问题 | `incidents/{FS-TXXXX}-{简述}-{日期}/` | 排查→根因→修复→沉淀 |
| 踩坑（配置/环境） | `memory/bad-case-index.md` BCI-NNN | 根因→现象→预防 Gate |
| 调研 / 选型 | `research/` | 技术调研、方案对比 |
| 规则 / 红线 | `rules/constitution.md` / 场景 rules | 同类错误复发 → 升级 Gate |
| 契约变更 | `contracts/` + `contract-change-log.md` | 跨服务握手协议变化 |
| harness 组件变更 | `CHANGELOG.md` | 新增/调整/废弃组件 |

## 三、约束/铁律

- **举一反三**：坑→BCI→Gate→下次自动拦截；没有沉淀的排查 = 白干。
- **本地轮回**：想法→调研→澄清→立项→落地→实战→登记，每产出有落点，零黑盒。
- **循环门禁**：治理是节奏不是事件——周期跑 `harness-governance` 审计 + `harness-size.sh -g` 防回弹。
- **先查后写**：知识只记一遍，沉淀前先搜 incidents/BCI/research 是否已有。
- **RED-5 追加式**：反哺只做加法，不覆盖已有红线/规则/枚举值。
