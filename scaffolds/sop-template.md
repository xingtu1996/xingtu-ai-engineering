# SOP 模板（通用）

> 用途：任何可标准化流程都可写成 SOP（部署/排查/开发/治理），AI 有样学样——先给骨架，每阶段必附真实案例，兼顾机器可循与人类可读。
> 创建步骤：① 找案例（research/incidents/specs 已落地实例）→ ② 套本文骨架 → ③ 每阶段填「操作/命令/验证/产出」+ 真实案例 → ④ 关联案例链接 → ⑤ 记版本历史。

## 一、SOP 骨架

### 1. 标题
`# {流程名} SOP（{场景}）` + 引用块：来源/用途/适用范围/体积。

### 2. 环境/前置条件
环境、凭据、依赖、已构建产物。缺一项则终止。

### 3. 步骤（阶段化）
每阶段统一四要素：

| 要素 | 要求 |
|------|------|
| 操作 | 做什么（一句话） |
| 命令 | 可执行命令/接口 |
| 验证 | 怎么算过（断言） |
| 产出 | 交付物 |

**铁律：每阶段附一条真实案例**（`例：…`），禁止空骨架。

### 4. 注意事项
坑/边界/回滚点。例：先 pull 再改 gitops、一次只改一个服务。

### 5. 与它环境区别（如有）
对比表：项 | 环境A | 环境B（如 SIT/UAT、dev/prod）。

### 6. 案例链接
关联已落地 SOP 与实例文档。

### 7. 版本历史
日期 | 版本 | 变更。
