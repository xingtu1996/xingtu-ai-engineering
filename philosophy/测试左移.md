# 理念-测试左移（Shift-Left Testing）

> 定义：**测试左移 = 验证从生命周期末端移到最早可行阶段，缺陷在引入时当场消灭而非末端兜底。** 内核：质量是造出来的，不是测出来的。
> 渊源：源自制造业质量前移——日本 TQC「品質は工程で作り込む」→ 丰田安灯/自働化 Jidoka → 2001 软件界首提、2005 嵌入 CI/CD 测试金字塔。
> 示例企业依据：`rules/constitution.md` RED-8 + 测试金字塔 L1~L6。

## 一、深入浅出

- **一句话本质**：测试越早越便宜——Bug 越晚发现，修复成本指数上升（单测 1x → 系统测试 40x → 生产 100x+）。
- **反模式**：全堆 UAT 测（晚测=修一漏仨）；写完才补测试（马后炮）；晚期用例照搬提前；末端 QA 把关当质量阀。

## 二、示例企业实践对应

- **RED-8 TDD 左移**：编译→本地启动→curl 验证→合并，能本地验证不等 SIT。
- **金字塔自下而上**：L1 单测（≥85%）→ L2 契约 → L3 E2E → L4 变异 → L5 静态 → L6 安全；底座先铺。
- **本地测试模板**：`方法-本地测试模板.md`（build.sh 零错误 + curl 全链路 + RED-6 清理）。
- **Spec/BDD 前置**：AC 可测试化，spec 先于代码，测试即活契约。

## 三、检查清单

```
□ 测试前置了吗？（先 AC/用例后代码？）
□ 本地验证过了吗？（编译→启动→curl 全链路？）
□ 单测先行吗？（L1 先铺？）
□ 金字塔自下而上吗？（底座厚吗？）
□ 反模式中招吗？（全堆 UAT / 写完补测？）
```
