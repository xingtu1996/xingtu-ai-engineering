# 方法-对抗审查（Adversarial Review）

> 定义：**对抗审查（Adversarial Review）** = 多个对立视角独立审查同一对象，交叉验证后仅保留高置信度发现。单一视角审查有固有盲区。
> 引用备案：ai-jury 跨供应商实证——单模型漏检种子缺陷（最佳 67%），四供应商评审团 100%；《Debate Round》——交叉质询才出价值（失败模式不相关，互补消除盲区）。

## 一、深入浅出

**一句话本质**：多角色独立挑刺，交叉验证消除单视角盲区。

**反模式**：① 单角色自我审查 → 盲区漏检（单模型最优仅 67%）；② 并行不交叉 → 各说各话，更贵的单审查；③ LLM 当法官 → 烧 token 且偏袒（应脚本实测）。

## 二、示例企业实践对应（引用不复制）

## 三、P0/P1/P2 分级报告格式

> 样板：四方对抗审查报告（P0 11/P1 14/P2 7 项 + 落地三步 + 亮点保留）。

**P0 必须修**（不修 = 对外失分 / 结论不成立）

| # | 完善点 | 来源 | 严重度 |
|---|--------|:--:|:--:|
| 1 | {缺陷} | {角色} | 🔴 |

**P1 应修**（影响可信度/质量闭环）｜**P2 完善**（补齐闭环）— 同表，🟡/🟢。

**落地建议（三步）**：① 立即修对外硬伤（P0 速修）→ ② 定交付形态/需人决策项 → ③ 执行期补强（P1核心+P2闭环）。
**亮点保留**：{经得起追问的部分，不动}。

## 四、骨架：对抗审查工作流

```
触发（对抗审查/审 Spec/审 PR/多视角）
① 角色分配  轻量 2 角色串行 / 标准 3 角色并行 / 重量 +领域专家（TKR-5）
② 独立审查  Refuter+Optimizer+Auditor 并行，各找 3-7 条（Caveman 精简）
③ 交叉验证  脚本 grep/ls/diff 实测 + Filter 拦截低质发现（≥30%）
④ 分级报告  P0/P1/P2 表 + 落地三步 + 亮点保留
⑤ 修复闭环  🔴 立即修 → 🟡 排期 → 🟢 记录；结果写回审查记录章节
```

**节奏**：独立并行 → 交叉（脚本非 LLM）→ 人审 checkpoint → 修复 → 复核。

## 五、适用边界

- **用**：Spec/设计、高风险变更（计费/库存）、跨 3+ 服务、生产事故复盘
- **不用**：单文件 <20 行小改动（普通 review 即可；轻量 2 角色串行封顶）
