# 方法-工单回复（Ticket Response / Incident Reply）

> 定义：生产问题对外回复的结构化表达——先定性再动码、责任到人、证据闭环。引用备案：TICKET-001/5294/5326/5327（memory/incident-reply-preferences.md）。

## 一、深入浅出

**本质**：对外回复 = 定性+责任+证据+闭环——不甩锅也不揽责，把"发生了什么、为什么、谁负责、怎么办、已确认"讲清。

**反模式**：① 只答现象不答根因；② 无责任追溯；③ 不回执闭环；④ AI 单方下定性。

## 二、定性五分类

| # | 定性 | 判定依据 | 处置 |
|---|------|---------|------|
| 1 | 代码缺陷 | 代码+数据证据 | 出修复方案 |
| 2 | 功能缺失 | 需求对比实现缺口 | 走需求/迭代 |
| 3 | 业务操作规范 | 功能完整未被操作 | BUG 转需求，列 D1~Dn 清单，暂不出方案 |
| 4 | 三方接口数据配置 | 三方/配置侧 | 转三方或配置修复 |
| 5 | 回归 | git 对比近期提交 | 定位引入 commit |

判定：数据 > 代码 > 描述。是否物料项目（纯赠品/纯物料→4.10.05.05~.10）明确 是/否/待定。

## 三、示例企业实践对应

| 方法论 | 示例企业落地 |
|--------|---------|
| 一工单一目录 | `{TICKET-XXXX}-{简述}-{YYYYMMDD}/` |
| 三件套 | AI协作排查+工单回复+定性分析 |
| 责任追溯到人 | git log/blame 追引入人+需求单号；独立仓库先确认 |
| 版本化闭环确认 | V1→V3.x；状态 ✅已结束/待确认；艾特相关方 |

## 四、骨架

```
① 结论（一句话）  定性+根因+证据（代码/数据/日志三链）
② 排查结论       功能链完整? 现状+实测+证据引用
③ 影响范围       阻塞? 同类单数量
④ 修复方案       立即(存量)/需求口径确认/流程监控
⑤ 验证           Playwright/SQL/SLS
⑥ 责任归属       责任方+物料项目+回归/三方/数据
⑦ 闭环回执       状态+待确认项+艾特相关方
```

## 五、检查清单

```
□ 定性清晰?（五分类之一）
□ 证据三链?（代码+数据+日志）
□ 责任到人?（引入人+需求单号）
□ 闭环回执?（状态+艾特相关方）
□ 是否物料项目?（是/否/待定）
```
