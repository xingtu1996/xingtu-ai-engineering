# UI 自动化测试模板（UI Automation Testing — Playwright）

> 定义：界面自动化测试——脚本模拟真实用户点击/输入/浏览，验证界面功能与交互符合预期。属测试金字塔 **L3 E2E**（UI 视角）。
> 关联：`rules/e2e-testing-rules.md` ＋ `memory/fs-e2e-login-playwright.md` ＋ `templates/E2E测试报告模板.md`。

## 深入浅出

**一句话本质**：模拟用户操作，验证「界面看得见的行为」符合预期。

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 只截图不断言 | 没验证，错也 PASS | 每用例至少一条断言 |
| 选择器脆弱（深层 class/位置） | 改样式即碎 | 优先 text/role/getByTestId |
| 界面看到 ≠ 落库正确 | 数据没写 | 关键用例 UI + db-query 双验证 |
| 一用例跑全流程 | 失败难定位 | 一用例一场景，前置造数据 |

## 示例企业实践

| 环节 | 做法 |
|------|------|
| 工具 | Playwright MCP（`.mcp.json` 配置，未加载 `/mcp` 重连）；产物 `.playwright-mcp/page-*.png` |
| 登录 | SSO：`fs-uat` → 企业统一认证 → 回跳 code；账号/密码见本地 config.yaml（不公开） |
| 双验证 | UI 断言后 db-query 查实际字段（提交/库存/日志必查） |
| 截图 | `TC-{Ticket}-AC{xx}-{场景}.png`（编号+场景中文）；存 spec 目录；禁用/二次确认/报错必截 |
| 结果 | 在线表格「AI 测试结果」列，测试人=AI，含时间+落库证据 |

## 骨架（用例）

```
TC-{Ticket}-AC{xx}-{场景}
前置：
  1. 已登录后台（SSO）且有权限
  2. 测试数据就绪（订单/店铺/活动）
步骤：
  1. 打开 {页面/路径}
  2. {选择/输入/点击}
  3. {提交/查看结果}
断言：
  1. {元素可见/文案/按钮禁用}（UI）
  2. {落库字段/状态}（db-query）
截图：TC-{Ticket}-AC{xx}-{场景}.png
```

**元素定位**（优先序）：`getByRole`/`getByText`（语义）→ `getByTestId`/数据属性（稳定）→ label 关联 → 兜底 CSS。禁：位置索引（`nth(2)`）与深层 class 链。
